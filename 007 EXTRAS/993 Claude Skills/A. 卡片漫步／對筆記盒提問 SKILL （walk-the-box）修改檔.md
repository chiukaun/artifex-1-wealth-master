
# 對筆記盒提問 SKILL（walk-the-box）

## 任務

拿一個問題，在筆記盒裡漫步，看看筆記盒對這個問題怎麼說。

這支 SKILL 是**唯讀的**——只走、只看、只回報，不歸檔、不建連結、不改任何檔案。它的工作是當思考的雷達，不是檔案管理員。

要把回報物質化成新卡或新連結，再交給 [[card-link-index]] SKILL。

## 核心心態

你不是「拿問題去搜資料」。你是帶著問題去在筆記盒走一段路。

差別在於：
- 搜資料的目標是「找到那張對的卡」——找到就停
- 漫步的目標是「累積到足夠脈絡為止」——一張一張讀，讓筆記盒慢慢顯影對這個問題的想法

漫步過程中你會經過很多卡。有些直接相關、有些只是路過、有些一開始看起來不相關但讀完才發現偷偷接到問題。**不要急著縫結論**——先走，走完再看。

這跟整個筆記盒的全域搜尋不一樣的地方：embedding 搜尋是一次撈一堆相似的卡；漫步是順著筆記盒**自己已經建好的連結結構**走，所以走過的路徑本身就帶著筆記盒的歷史脈絡。兩個工具都可以用，但漫步是這支 SKILL 的核心動作。

---

## 流程

### 1. 解析問題

讀使用者的問題，先複述一次給使用者看，確認你抓對：
- **核心關鍵字**是哪幾個？（問題裡的概念詞，不是問句句式）
- **是哪種問法**？
  - 主張式：問題已經有假設，要驗證或推翻（例如「卡片越短越好嗎？」）
  - 探索式：問題開放，沒有預設答案（例如「索引頁該怎麼長？」）

如果問題太大、太抽象、或包了三個問題在一起 → 跟使用者商量先拆。一次漫步只回應一個問題。

### 2. 從索引頁找入口

到 `003 ATLAS/` 挑 **1~3 個最相關的索引頁**（檔名格式 `Index N - xxx.md`）。

不要貪多——多反而稀釋走的深度。

從每個索引頁挑 **1~3 個最相關的關鍵字**，每個關鍵字下會指向 1~4 張入口卡。
列出所有入口卡，這就是漫步的起點。

⚠️ 如果索引頁裡找不到合適關鍵字 → 跟使用者回報，可能：
- 問題不在筆記盒的覆蓋範圍內（誠實說）
- 問題對應的是還沒長出來的關鍵字（建議使用者考慮，但這支 SKILL 不動索引頁）

### 3. 漫步

從每張入口卡開始，跑下列迴圈：

```
讀目前這張卡的內容
→ 問：這張卡如何回應原問題？（記一句話）
→ 看「延伸」區的連結，問：哪一張最可能繼續回應問題？
→ 點開那張，回到迴圈第一步
```

#### 走多深？

**不設上限。** 走到「脈絡充足」為止——
- 你能對原問題說出有實質內容的回應
- 再讀下一張不太會增加新東西
- 走到某個分支底了，沒有更深的連結

由你自己根據問題內容判斷。可能五張就夠，也可能要走五十張。判斷的指南針只有一個：**回到原問題，現在能不能說出有實質的東西？**

#### 並行多條

可以同時走多條路徑——不同入口、或同入口的不同延伸分支。某條走死了，回頭換另一條。

#### 累積讀過的卡清單

每讀一張就記一筆：
```
[[卡名]] —— 一句話：這張回應問題的什麼面向
```

這份清單是後面三眼回看的材料。

#### 注意

⚠️ **不要偷懶停在表層**。入口卡通常太通用，真正的對話點在深層（三五層之後甚至更深）。

⚠️ **不要靠標題猜**。每張納入清單的卡都要點開讀內容——標題經常騙人。

⚠️ **不要中途縫結論**。漫步階段只記「這張回應什麼」，不寫整體分析。整體分析留到第 4 步。

---

### 4. 三眼回看

漫步結束（你判定脈絡充足）後，回頭看累積的卡清單，用三種眼睛各看一次。

#### 眼一：段落串

從讀過的卡裡，挑 **3~7 張能串成一條敘述線**回應問題的卡。

呈現方式：

```
段落串：[一句話描述這條串說什麼]

[[卡 A]] —— 起點，立下 X 主張
　↓
[[卡 B]] —— 把 X 推到 Y 情境
　↓
[[卡 C]] —— Y 情境下浮現的反例
　↓
[[卡 D]] —— 反例最後怎麼收
```

**只列卡、寫一句引路詞，不要縫成段落敘述。**

理由：縫成段落會把使用者自己「沿著讀過去」的發現感偷走（CLAUDE.md：「被推薦是審核，自己想到是發現」）。讓使用者自己沿著串點進去讀，自己縫意義。

如果讀過的卡沒辦法串成有意義的線 → 誠實說：「我走過這些卡，但它們各自回應問題的不同面向，沒有自然的串。」

#### 眼二：撞見

從讀過的卡裡，找**跟問題的關係偷偷藏起來的卡**——
- 拓樸距離遠（不在主路徑上、或來自意外的分支）
- 但語義上撞到問題的某個角落
- 第一眼看標題沒想到它跟問題有關，讀完才「啊」一聲

呈現方式：

```
撞見：

[[卡 X]]
（一句話講為什麼撞見——點出那個驚奇，但不要替使用者把驚奇解釋完）

[[卡 Y]]
（同上）
```

**寧缺勿濫**。沒有撞見就說沒有——硬湊出來的撞見會污染這個機制（CLAUDE.md 原則三的反面：多重儲存是為有意義的脈絡，不是為了連而連）。

#### 眼三：模式浮現

回看手邊**所有讀過的卡**，問自己：

> 有沒有某個模式，是這幾張卡都在繞著轉，但沒有任何一張卡直接把它點名？

模式可能是：
- **共同母題**：多張卡的底層共通點沒被命名
- **跨領域共鳴**：同一機制在不同領域反覆出現
- **隱形原則**：多張卡都在遵循一個從未被明說的原則
- **演化過程**：多張卡拼起來是一條進程但沒卡把路徑畫出來
- **辯論**：兩邊立場都有卡但沒卡點明張力
- ⋯⋯不拘形式

呈現方式：

```
⇨ 模式：[一段觀察，四五句話以內]
⇨ 這可能是建新卡的信號——但也可能我看錯，你怎麼看？
```

**這是這個 SKILL 真正的招牌動作。**

段落串跟撞見其他工具能做半套；模式浮現是只有「AI 帶著一整個漫步的記憶」才做得到的事——你看過五十張卡的當下，腦袋裡有這批卡的整體輪廓，使用者沒有，這個視角是你獨有的禮物。

寧缺勿濫，沒有就說沒有。但有就要認真寫——不要應付。

---

### 5. 收尾問句

報告最後，問使用者幾個可能的下一步：
- 哪一條路徑想繼續挖？要不要再跑一次更聚焦的漫步？
- 段落串裡哪張卡想點進去重讀？
- 模式觀察要不要長成新卡？（→ 接 `card-link-index` SKILL）
- 撞見裡有沒有哪張想建反向連結？（→ 接 `card-link-index` SKILL）

## 回報格式總覽

```
# 漫步回報：[問題]

## 我怎麼讀這個問題
[一兩句話複述]

## 入口
從 [[Index N - xxx]] 的「關鍵字 A」、「關鍵字 B」進入
出發卡：[[卡 1]]、[[卡 2]]

## 漫步路徑
- [[卡 1]] → [[卡 a]] → [[卡 b]] → ⋯ stop（讀了 N 張）
- [[卡 2]] → [[卡 c]] → ⋯ stop（讀了 M 張）

## 段落串
[眼一]

## 撞見
[眼二，沒有就說沒有]

## 模式浮現
[眼三，沒有就說沒有]

## 下一步問你
[列 2~4 個可能的下一步]
```

## 注意事項

1. **唯讀**：絕對不動筆記盒的檔案結構、不建連結、不改任何卡的內容。要動結構交給 `card-link-index`。
2. **要點開讀**：每張納入清單的卡都必須讀過內容，不靠標題猜。
3. **不縫敘述**：段落串只是路標，不是答案。把縫意義的工作留給使用者。
4. **三眼都允許「沒有」**：硬湊段落串、撞見、模式只會污染這支 SKILL 的可信度。寧可回報「這次漫步沒有撞見」也不要編。
5. **走得夠深**：表層不會有對話點。三五層之後才開始有東西。
