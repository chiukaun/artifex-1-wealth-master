# 工作專案系統藍圖 v2

> v1 藍圖（含軌道圖、STATUS LOG、開工／收工／復盤儀式三件套）已歸檔於
> `008 EXTRAS/994 Archived/v1 工作系統殘骸 2026-05-24/000 工作專案系統藍圖 v1.md`。
> 本檔是 v2 重寫版本——拿掉「天」這個單位，按鈕觸發、純被動執行。

---

## 1. 核心命題

> **系統的存在應該是消除使用者工作的阻力，不是增加阻力。**

從 v1 的「儀式驅動的打卡系統」（開工／收工／復盤）改成 v2 的「按鈕觸發的狀態鏡」（全局刷新）。

- 拿掉「天」這個單位——按按鈕才看狀態，沒按就不打擾
- 拿掉軌道圖整份文件——「我現在要做什麼」在對話視窗即時產出
- 拿掉開工／收工儀式——合併為 `global-refresh` 一支 SKILL
- 拿掉 STATUS LOG 容器——動作分散到 WORKBOOK、自由寫作、git log
- 復盤剝離到個人系統領域（個人系統重構時處理，本系統不動）

## 2. 設計哲學

> 詳見 [[CLAUDE]] 「AI 哲學」，這裡只列工作系統落地時的具體展開。

1. **降低操作摩擦，保留判斷摩擦**——AI 處理格式／查資料／整理結構；「怎麼理解、怎麼歸類、跟什麼連結」這些判斷留給使用者。
2. **DASHBOARD 是萃取層**——所有上面的內容都是「從原始材料萃取出來的東西」。原始留在累積層（WORKBOOK 工作日誌、git log、自由寫作、AI 對話 jsonl），DASHBOARD 只放凝練觀察。
3. **資料層次：原始 → WORKBOOK → DASHBOARD**——資訊流向單向，不可反過來。
4. **觀察 vs 推測 vs 結論**（[[CLAUDE]] 「全局觀規則」）——SKILL 寫入時三類陳述要分明，不替使用者拍板。
5. **不憑空生成內容**——所有寫入都要有依據（工作日誌、git diff、對話 transcript）；沒依據就空白。

## 3. 三層架構

```
SOURCE 粗資料層 ──→ WORKBOOK 累積層 ──→ DASHBOARD 萃取層 ──→ 對話視窗產出
  ├ AI 對話 jsonl                         （📅 時程目標
  ├ git log/diff                         + 各專案兩行摘要）
  ├ 自由寫作 (002 FREEWRITE/)
  └ 手札卡片 (001 INBOX/YYYY-MM-DD 手札：xxx)
```

### 3.1 SOURCE 粗資料層

| 來源 | 位置 | 用途 |
|---|---|---|
| AI 對話 jsonl | `~/.claude/projects/<vault-encoded>/*.jsonl` | 工作思考 + 操作軌跡（被 global-refresh 萃取） |
| git log/diff | vault 根 | 文件改動的 ground truth（被 global-refresh 萃取手札用） |
| 自由寫作 | `002 FREEWRITE/YYYY-MM-DD.md` | 早上的腦袋傾倒（被 free-writing-extract 分發） |
| 手札卡片 | `001 INBOX/YYYY-MM-DD 手札：xxx.md` | global-refresh 從 git diff 抽離出的手寫思考過程 |

### 3.2 WORKBOOK 累積層

位置：`006 PROJECT CARDS/`

**檔名約定**（重要——SKILL 用來辨識）：

| 類型 | 格式 | 範例 |
|---|---|---|
| **WORKBOOK 主檔** | `【 {D./C./A./F.} {名稱} 】.md` | `【 D. AI 年會 】.md`、`【 F. 報稅 】.md` |
| 同領域產出文件 | `{D./C./A./F.} {名稱}.md`（不加【】） | `D. 對話紀錄萃取 SKILL（修改檔）.md` |

⚠️ **【】是 WORKBOOK 主檔的識別記號**——SKILL 判斷「該寫進哪個 WORKBOOK」時只認【】格式，避免誤判同領域產出文件。

**WORKBOOK 內結構**（見 `007 EXTRAS/999 Template/2 Workbook.md`）：

```
---frontmatter---
type: 工作
orbit: 🔴/🟢/🟡/⚪
last_updated: YYYY-MM-DD
---

> [!info] 📍 現況       ← 一句話，跟 DASHBOARD 一字不差
> [!example] ▶️ 下一步   ← 一條，跟 DASHBOARD 一字不差

【 願景 / 目標 】

> [!abstract]- Timeline
> [!question]- 下一步行動    ← 探索／風險／痛點，🔴🟡🔵 熱度
> [!quote]- 領悟
> [!info]- 會議記錄

▋ 目前產出
▋ ⏰ 死線清單              ← 只裝「明確日期事項」或「外部硬死線」，可空白

## 📝 工作日誌            ← 累積，最新在上
------------` YYYY-MM-DD `------------
▋ 主題
⇨ 領悟／操作／決定／產出
```

### 3.3 DASHBOARD 萃取層

| DASHBOARD | 路徑 | 內容 |
|---|---|---|
| 工作 DASHBOARD | `004 PROJECT/DASHBOARD - 工作專案.md` | 📅 時程目標（週／月／季）＋三條線（卡片筆記：電馭大腦／電馭寫作／創作者）下的兩行摘要（現況／下一步） |

| 檔名前綴 | 屬於哪條線 |
|---|---|
| `【 D. 】` | 卡片筆記：電馭大腦 |

## 4. SKILL 清冊（v2）

### 4.1 核心 SKILL

| SKILL | 角色 | 觸發 |
|---|---|---|
| `global-refresh` | 主協調器——把 SOURCE 萃取分發到 WORKBOOK，同步 DASHBOARD，產出「我現在要做什麼」 | 「全局刷新」「刷新」「我現在要做什麼」「refresh」按鈕觸發 |
| `conversation-extract` | 把 AI 對話 turn 萃取進 WORKBOOK 工作日誌（含與已手寫日誌去重） | 主動：「整理對話到日誌」／被 global-refresh dispatch |
| `free-writing-extract` | 把自由寫作分發到對應 WORKBOOK／卡片／生活雜事 | 主動：「整理自由寫作」／被 global-refresh dispatch |
| `freewrite-regroup` | 把跳躍式自由寫作重新排列，散落各處但講同一件事的段落聚在一起（原文逐字保留、**唯讀不寫檔**，只在對話視窗輸出）。可當 free-writing-extract 的前置視野 | 主動：「重組自由寫作」「把相近的內容放一起」「這篇我寫了哪些點」 |
| `work-project-update` | 把工作日誌整理到 WORKBOOK 對應 callout，同步 DASHBOARD 兩行摘要 | 主動：「整理專案頁」／被 global-refresh dispatch |

### 4.2 卡片筆記 SKILL

| SKILL | 角色 |
|---|---|
| `card-link-index` | 把寫好正文的卡片歸檔進筆記網絡——串／撞見連結、長索引頁（「卡片進來」方向） |
| `walk-the-box` | 拿問題去筆記盒漫步，三眼回看：段落串／撞見／模式浮現（「問題進去」方向，唯讀） |
| `semantic-search` | Smart Connections AI embedding 語義搜尋 |
| `extract-book` | 從電子書序列萃取卡片筆記（5 鏡頭漸進深讀，slash command + book-card-extractor subagent） |

### 4.3 個人領域 SKILL（v2 不動，留待個人系統重構）

| SKILL | 狀態 |
|---|---|
| `fu-pan` | 保留，等個人系統重構時統一處理 |

### 4.4 系統維護 SKILL

| SKILL | 角色 |
|---|---|
| `skill-audit` | 系統結構改動時掃所有 SKILL 找受影響部分 |
| `skill-creator` | 建立／修改／優化 SKILL |
| `update-config` | 設定 `settings.json`、hook、權限、env 等 |

## 5. 資料流（按時間順序）

### 5.1 平日工作循環

```
1. 你開始工作——AI 對話 jsonl 累積、git auto-commit 累積
2. 你寫自由寫作（早上）——002 FREEWRITE/YYYY-MM-DD.md
3. 你想知道狀態 → 按「全局刷新」
   ↓
4. global-refresh 跑：
   Step 1: AI 對話切片
     - 1.4.5: 摘要表給使用者勾選哪些整理／忽略／換 WORKBOOK
     - 1.5: 對選中的 dispatch conversation-extract → WORKBOOK 工作日誌
   Step 2: git diff → 手札卡片 + wikilink 寫進工作日誌
   Step 3: 自由寫作 → free-writing-extract → 分發
   Step 4: work-project-update → 同步 callout ＋ DASHBOARD
   Step 5: DASHBOARD 檢查 + 自動推進
     - 5.2: 偵測到當週漂移 → 自動滾舊週為「✅ 結束」+ 插入新週範本 + 預填 7 天內死線
     - 5.3: 死線過期 → 提醒（不自動寫）
   Step 6: 對話視窗產出「我現在要做什麼」
   Step 7: 更新 last-refresh.txt
   ↓
5. 你看到狀態 → 決定下一步要做什麼
```

### 5.2 一次性／策略性決定

DASHBOARD「📅 時程目標」拆兩層：
- **節奏層**（當週標記滾動 W{N} → W{N+1}）→ AI 自動推進：偵測漂移時把舊週標 `✅ 結束`、上方插入新週範本、預填 7 天內死線
- **策略層**（每週／月／季的具體工作項目）→ 使用者手動填，AI 只預留骨架

## 6. 軌道燈號

| 燈號 | 意思 | 說明 |
|---|---|---|
| 🔴 | 優先進行中 | 卡住了、快到期、需要馬上處理 |
| 🟢 | 正常進行中 | 按計畫進行，無時程壓力 |
| 🟡 | Pending | 有外部因素或其他專案因素卡住 |
| ⚪ | 暫時關閉 | 目前不推進 |

orbit 預設不動——除非工作日誌明確提到狀態變化，否則保留原值。frontmatter 跟 DASHBOARD 不一致時，以 frontmatter 為主，DASHBOARD 對齊。

### 已拿掉

- ❌ **軌道圖**（檔案）——「現在要做什麼」改在對話視窗產出
- ❌ **STATUS LOG**（每週狀態日誌）——動作分散到 WORKBOOK／自由寫作／git log
- ❌ **kai-gong／shou-gong**（開工／收工儀式）——合併為 global-refresh
- ❌ **meeting-notes-organizer**——草稿狀態，下次會議實測後再開發
- ❌ **WORKBOOK 🗒️ 手札 callout**——改用獨立卡片＋工作日誌 wikilink 形式（5/25 修正）

### 已加入

- ✅ **global-refresh SKILL**——核心新 SKILL，取代開工／收工
- ✅ **conversation-extract SKILL**——AI 對話成 first-class SOURCE
- ✅ **WORKBOOK 範本加 ⏰ 死線清單**——明確日期事項用，可空白
- ✅ **WORKBOOK 主檔【 】命名約定**——SKILL 識別主檔 vs 同領域產出文件
- ✅ **DASHBOARD 時程目標三層**：近兩週週計畫 ＋ 月計畫 ＋ 季／半年目標
- ✅ **last-refresh.txt 時間戳機制**——`.claude/last-refresh.txt`，global-refresh 完整成功才更新

### 設計拍板

- **對話歸屬**：信心夠就自動寫，模糊才提候選（事實辨識 vs 詮釋判斷）
- **手札抽離**：半自動候選（思考過程值不值得留檔是價值判斷，留給使用者）
- **自由寫作身心內容**：留原檔不萃取（v2 free-writing-extract 瘦身）
- **全局刷新**：純被動按按鈕，不自動排程
- **個人 DASHBOARD**：本輪不動（個人系統重構時統一處理）

## 9. 辭典

| 詞 | 定義 |
|---|---|
| **WORKBOOK** | 一個專案的完整工作本——有 frontmatter、現況、下一步、工作日誌等完整結構。檔名加【】 |
| **WORKBOOK 主檔** | 出現在 DASHBOARD 上的最高層級專案頁，加【】記號 |
| **同領域產出文件** | WORKBOOK 底下的產出（卡片、草稿、會議記錄、SKILL 修改檔），不加【】 |
| **SOURCE** | 粗資料來源（AI 對話 jsonl、git log、自由寫作、手札卡片）|
| **工作日誌** | WORKBOOK 內的 `## 📝 工作日誌` 區塊——每次工作推進的累積區，最新在上 |
| **▋ 主題** | 工作日誌一次推進的條目標題 |
| **⇨ 子標題** | 工作日誌一個主題下的四種子項目：領悟／操作／決定／產出 |
| **手札** | 從 git diff 抽離出的手寫思考過程，獨立卡片放 `001 INBOX/` |
| **last-refresh** | `.claude/last-refresh.txt` 時間戳，記錄上次全局刷新成功時間 |
| **全局刷新** | global-refresh SKILL 的執行——把 SOURCE 萃取分發到 WORKBOOK，同步 DASHBOARD，產出「我現在要做什麼」 |
| **軌道燈號** | 🔴 優先進行中／🟢 正常進行中／🟡 Pending／⚪ 暫時關閉 |
| **下一步行動** | WORKBOOK 內的 callout，放未來可能要做或要消化的事情（探索／風險／痛點／具體待推動），全部混放，靠 🔴／🟡／🔵 熱度區分 |
| **▶️ 下一步** | WORKBOOK 內的 callout，單條（Via Negativa），跟 DASHBOARD 一字不差 |
| **📍 現況** | WORKBOOK 內的 callout，一句話事實型，跟 DASHBOARD 一字不差 |
