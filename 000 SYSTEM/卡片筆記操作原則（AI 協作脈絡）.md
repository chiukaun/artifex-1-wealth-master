
### 一、新卡片寫入：簡短、草率、核心想法

**原則**：一張卡片的內容應是好讀易懂，簡短明白。

**邏輯**：
- 魯曼用 A6 卡片，物理上無法寫長；他的卡片大多只有兩三句，很多只有一句話。
- 一張卡片如果寫成一整篇文章，脈絡就固型了，很難被多重儲存（見原則三）
- 在數位工具上可以不限長度，但長度越長，理解成本就越大，必須注意這點。
- 反過來說：如果一張卡片可以被多重儲存，代表它本來兩三句能講完；你用 1000 字寫反而讓它死掉

結論：「卡片怎樣寫才算好？」——輕鬆寫、突發靈感也行，不需要完整、不需要寫到可以發脆、不需要有任何工整。**澄清的工作交給整個筆記盒，不交給單張卡片。**

**AI 操作指引**：
- 不要替使用者潤飾、工整化、或擴寫成「完整版」，盡可能保留使用者自己的語氣與用詞。
- 不要把 1000 字的東西當一張卡片放進去——如果真的有那麼多話，那是文章稿，不是卡片

---

### 二、局部連結，不做分類

**原則**：將新卡片放入筆記盒時，不問「這張該歸哪個索引頁」，只問「這張可以連到哪些既有卡片」。

**邏輯**：
- 魯曼寫新卡片時不會想「這屬於哪個主題區塊」；他只想「這張可以接在哪張舊卡後面」，然後沿用舊卡編號
- 結果：一個編號區塊裡的主題會自然分叉（魯曼稱為「分叉能力」Verzweigungsfähigkeit，Schmidt 譯為 forking capacity）——例如他的第 21 區塊原本是「功能主義」，卻會一路走到「階級社會」
- **編號只是地址，地址不會意味著這裡的住戶是什麼個性**——卡片的意義由連結脈絡決定，不由位置決定
- 好處是速度：分類決策越簡單 → 寫入摩擦越小 → 願意寫下的想法越多 → 系統越豐富

結論：「這張筆記應該歸類到哪一個索引頁下面？」——現在知道不需要歸類到索引頁下面，只需要找到既有筆記給它連結。

**AI 操作指引**：
- 對新卡片要做的判斷是：它可以跟哪些既有卡片產生有意義的連結？

---

### 三、多重儲存

**原則**：想到三種連結可能，就在三種位置都建。不要找「最正確」的那個位置。

**邏輯**：
1. **降低遺失風險**：同一個主題可以從多個入口找到
2. **脈絡構成意義**：同一張卡片放在「決策理論」區塊 vs「古代社會」區塊，會被周圍的卡片賦予不同的解讀意義
3. **未來開放性**：不把自己鎖死在剛性分類裡，系統可以自然演化

魯曼原文 (9/8b2)：「多重儲存是存放複雜資訊的必要手段。」

**AI 操作指引**：
- 幫加恩找連結時，給出所有合理的候選，不要只給「最貼切」的那張——讓他選擇哪幾個值得建。
- 複雜主題優先多點建連結；簡單、獨特的主題一個連結也可以

---

## 四、不刪除筆記：卡片盒是化糞池

**原則**：遇到你認為「錯」的舊筆記，不要刪除；在後面新增一張卡片說明為什麼錯。

**邏輯**：
- 魯曼原文 (9/8a2)：「卡片筆記是化糞池——不要只放那些精心處理好的卡片。暫停檢驗與決策，這也是速度的問題。」
- 「錯誤」是當下的脈絡判定的——脈絡變了，錯誤可能翻案
- 卡片的內容本身不是重點，它被放在什麼脈絡下解讀才是重點
- 筆記盒不是「精品店」（只放處理好的），是「化糞池」（澄清的工作由整體系統完成，不由單張卡片完成）

**AI 操作指引**：
- 絕對不要刪除加恩已有的卡片，即使它看起來過時、錯誤、或重複
- 遇到「錯」的舊卡 → 新增反駁卡，連結到原卡
- 遇到重複內容則為例外 → 應選擇較少連結的那張刪除。

## 五、索引頁是入口，不是目錄

**原則**：索引頁由關鍵字組成，一個關鍵字指向 1~4 張入口卡（大多 1~2 張，只有很大的主題才到 4 張）。

**邏輯**：
- 魯曼 9 萬張卡片只對應約 3200 個關鍵字索引——索引是刻意保持不完整的
- 索引不是為了列出所有相關卡片，而是提供進入卡片網絡的「入口點」
- 通過一個關鍵字找到 1~4 張入口卡，然後順著卡片上的連結遊走，遲早會走到所有相關內容
- 入口卡可以是 hub 卡、深層子節點、甚至人名卡——任何能快速帶人進入網絡的卡都行

關鍵字指向邏輯：
- 當關鍵字慨念可以跨多個主題 → 指向多個大區的卡片筆記
- 當關鍵字在單一主題下深度發展 → 指向同一區的不同子節點
- **每張入口卡應導向不同方向，才有意義**——不要四張都指向同一個分支

```
以 003 ATLAS/債 為範例：

道德
[[14. 「欠債就該還」是一句聽起來太像常識的話]]
[[17. 摔碎泥板：史上第一次債務豁免，也是「自由」這個字第一次出現]]

[[15. 付現金曾經是無賴的標記]]

[[16. 問「這筆利息在補償什麼」，比問「利率幾趴」深一層]]

↑ 入口卡編號散在不同的思路源頭（14、17、15、16 是四張根卡，

```


**AI 操作指引**：
- 不要把索引頁做成目錄式的臃腫清單
- 索引頁整理的目標：把大量卡片收斂成少數關鍵字，每個關鍵字背後 1~4 張精選入口卡，用連結遊走解決查找的問題。
- 如果某個關鍵字下連結超過 4 張卡片 → 拆分出子關鍵字，或篩選出最有代表性的入口

### 操作卡片筆記時的核心直覺

當你要幫加恩做操作判斷時，回到這五條去想——不要讓「看起來整齊」「看起來完整」的直覺蓋掉原則。魯曼的系統之所以有效，正是因為它反直覺地**不整齊、不完整、速度優先**。

```
【   TYPICAL CARD-LINK STRUCTURE   】 

          ┌──────────────────────────────┐
          │  INDEX (keywords, sparse)    │
          └──────────────────────────────┘
             [alpha]            [beta]
                │                  │
                ▼                  ▼
            ┌───────┐          ┌───────┐
            │   A   │          │   B   │
            └───┬───┘          └───┬───┘
                │                  │
           ┌────┴────┐        ┌────┴────┐
           ▼         ▼        ▼         ▼
         ┌────┐  ┌────┐    ┌────┐   ┌────┐
         │ a1 │  │ a2 │    │ b1 │   │ b2 │
         └──┬─┘  └──┬─┘    └──┬─┘   └──┬─┘
            │       │         │        │
            ▼       ▼         ▼        ▼
         ┌────┐  ┌─────┐   ╔═════╗  ┌────┐
         │a1a │  │ a2a ├──►║ b1a ║  │b2a │
         └────┘  └──┬──┘   ║  *  ║  └────┘
                    │      ╚═════╝
                    ▼          ^
                 ┌─────┐       │
                 │ a2b │       │
                 └──┬──┘   (hub: many
                    │      paths converge)
                    ▼
                 ┌──────┐
                 │ a2b1 │
                 └──────┘

圖例
─────
 ──►     連結方向（閱讀遊走路徑；也是新卡沿用舊卡編號的方向）
 入口卡   由索引關鍵字指向的卡——可以是任何一張卡
          （深層子節點、人名卡、hub 卡都可以）
 ★／╔╗   hub：多入度的高連結度節點——隨多重儲存「自然長出」，不是設計的
          入口卡不必然是 hub；hub 也不必然剛好被索引指到
 多重     寫新卡時若想到多種連結可能，就全建——例如 a2a 寫時，
          同時把它接在 a2 後面、也建連結跨到 b1a（跨脈絡連結）
 反駁     發現錯誤不刪，新卡直接接在錯卡後面、沿用編號
          （例：a2b1 是 a2b 的子編號；不是另開獨立卡）


這張圖體現的五條原則
──────────────────
 一、節點粒度小      每張卡兩三句 → 整張圖由大量小節點組成
 二、局部連結不分類  a2→a2a→a2b→a2b1 是沿鏈走，編號連續沿用主題沿鏈自然分叉（下游可能已經跟 A 差很遠）
 三、多重儲存        a2a 寫時同時建了跨到 b1a 的連結
                     → 鏈與鏈被織成網，不是一串串獨立的鏈
                     → 這類跨連結累積，讓某些節點自然長成 hub
 四、不刪錯的卡      a2b 被判定錯也不刪，a2b1 接在它後面反駁
                     編號連續 → 反駁跟原卡物理相鄰、並存
 五、索引刻意不完整  α、β 只點亮 A、B 兩張入口卡
                     其餘節點由順連結遊走發現（不由索引窮舉）
                     入口卡就是「能快速帶人進入網絡」的卡——不一定
                     是 hub，有時是 hub，有時是深層子節點或人名卡

```



簡記：
1. 寫入：好讀易懂，簡短明白。
2. 連結：只問能連到什麼，別問屬於哪類
3. 儲存：想到幾種就建幾種
4. 錯誤：不刪、不合併，用反駁卡對話
5. 索引：關鍵字 → 1~4 張入口 → 順連結遊走；索引刻意不完整
